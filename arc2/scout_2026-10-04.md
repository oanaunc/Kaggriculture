We scanned `kaggle kernels list` sorted by votes, date run, score (`scoreDescending`) and the search term "LB", plus the

## Findings
1. **No public notebook is outside the NVARC Qwen3-4B lineage and also shows evidence above ~34.** Every score claim
   comes from `sorokin/qwen3_4b_grids15_sft139` with per-task LoRA TTT, turbo DFS and kgmon, the same pipeline as ours.
   No milestone or writeup release appears in the topics. The newest threads are about queueing, a "Qwen 3.8 speed"
   thread and licences.
2. **Reruns of the verbatim perfpatch give different LB scores.** The source hashes are identical (md5 `57da1db3...`):
   | Notebook | Code | Public LB (source) |
   |---|---|---|
   | `mikelou1/arc-agi2-lb33-89-minimal-perfpatch` | base | 33.89 (title) |
   | `uninhibitedscholar/arc2-v6-perfpatch-32-22-fork` | byte-identical | 32.22 (title) |
   | `nitish5236goel/arc2-ttt-v2` "ttt_baseline v3" | frozen replica of the 33.89 notebook | 29.31 (markdown) |
   | `medvax/arc-agi-2-qwen-ttt-with-symbolic-fallback` v1 | perfpatch plus a fallback that never fires | 28.89 (markdown) |
   | `junaid512/arc-agi-31-11` | commented NVARC rewrite | 31.11 (title) |
   | **ours** v1, rerun twice | perfpatch plus hardening and stable seeds | 28.61 / 28.06 |

   The base seeds augmentation with `hash(bk)`, which changes with PYTHONHASHSEED on every run, so its LB is close to a
   lottery between about 29 and 34. The mean of the verbatim runs is about 31.8. Our fixed seeds make our runs repeat each
   other (±0.5), but we may have fixed a low draw. Our other changes (cheap-first ordering, retry pass, 120 s start cutoff)
   might also cost a few points. Neither cause is proven.

## Candidate and fork

- Hardware: 4x L4 (`NvidiaL4`), GPU on, internet off, pinned BYOD docker image. Runtime is about 12 h (global stop at 12 h − 10 min).
- Inputs: the model `sorokin/qwen3_4b_grids15_sft139/Transformers/bfloat16/1` (Apache-2.0) and the utility script
  `sorokin/pip-install-unsloth-flash-patch`. Both are public and attachable. Code shared publicly for the competition
  counts as OSI-licensed under Rules §6b.
- Fork: `arc2/fork_perfpatch/` holds the notebook byte-identical to the original, renamed to `arc2-perfpatch-ours.ipynb`.
  Only the metadata changed: id `oanaunciuleanu/arc2-perfpatch-ours`, private, with the same sources, docker image and
  machine shape. It has not been pushed or submitted.

## Recommendation and risks
- Submit the fork unchanged as an A/B anchor against our 28.06-28.61. If it scores above 30, our changes or our fixed
  seeds are costing points. Bisect them: first move our stable seed salt off the current value, then revert cheap-first ordering.
- A single run has about ±2.5 of variance, so one submission cannot distinguish 29 from 32. Budget 2-3 runs per arm.
- The 33.89 is the best of many forked draws, so expect regression toward about 31.
- The top teams (77-84) use private methods. Nothing public comes close.
